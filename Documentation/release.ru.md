# Выпуск исходников

Как выпустить исходники проекта: что проверить до этого, как собрать архив, что опубликовать и что сделать после.
Выпуск — это архив одного коммита; ничего, кроме того, что лежит в git, в него не попадает: ни пакетов телефонов,
ни образов, ни сборок, ни прошивок, ни файлов Apple.

## 1. До выпуска

```sh
make check                                       # всё, что не требует телефона (то же, что CI)
tools/check-publishable.sh                       # ничего, что нельзя публиковать: бинарники, прошивки, файлы Apple, ключи
make ready && make day                           # день с телефоном (phone-test.ru.md), если он был с тех пор
```

Проверьте [whats-new.ru.md](whats-new.ru.md) и [CHANGELOG.md](../CHANGELOG.md): из разделов `## Unreleased: ...`
CHANGELOG собираются заметки к выпуску, так что в них должно быть всё, что изменилось, и ничего лишнего. Всё
закоммитьте: выпускается коммит, а не рабочая копия.

## 2. Архив

```sh
scripts/release.sh 1.0                           # проверки, затем build/release/
scripts/release.sh 1.0 --no-check                # без make check, если он только что прошёл
scripts/release.sh 1.0 --tag                     # и аннотированный тег v1.0 здесь
```

В `build/release/` появятся:

| Файл | Что это |
| --- | --- |
| `hakios-kernel-1.0.tar.gz` | Исходники коммита в папке `hakios-kernel-1.0/` и список его файлов `.tracked-files` |
| `SHA256SUMS` | Контрольная сумма архива |
| `NOTES.md` | Заметки к выпуску: разделы CHANGELOG, ещё не выпущенные |

Один и тот же коммит всегда даёт байт в байт один и тот же архив, так что любой может пересобрать его и сверить сумму.
В распакованном архиве `make check` проходит так же, как в git-копии: проверки идут по списку `.tracked-files`
(`tools/files.py`).

`release.sh` ничего никуда не отправляет. Публикуете вы сами:

```sh
git push origin v1.0                             # тег
```

и архив, `SHA256SUMS` и `NOTES.md` — туда, где выпускаете (страница выпуска на GitHub, например).

## 3. После выпуска

- В CHANGELOG.md переименуйте выпущенные разделы `## Unreleased: ...` в `## 1.0: ...`, чтобы следующий выпуск не
  повторил их в заметках, и закоммитьте.
- Образы телефонов выпускаются отдельно, в их собственных репозиториях: `make publish DEVICE=ИМЯ REPO=...`
  ([images.md](images.md)). В них нет ни данных Apple, ни образа системы.

## Если что-то не так

| Что сказано | Что это | Что делать |
| --- | --- | --- |
| `the checkout has changes that are not committed` | Есть незакоммиченные изменения | Закоммитьте или уберите их |
| `something that must not be published is in the repository` | `tools/check-publishable.sh` что-то нашёл | Его вывод назовёт файл; уберите его из git |
| `make check fails: build/release-check.log` | Проверки не прошли | В журнале видно, какая; исправьте и выпускайте снова |
| `the tag v1.0 is there already` | Такой тег уже есть | Другой номер версии |
